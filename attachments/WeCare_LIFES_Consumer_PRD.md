- Phase 1 → 先在 50+ 家诊所建立数据密度 → Phase 2 再启用消费者端

## 2. 他们每天面临什么痛苦？

### 患者的核心痛苦

**痛苦一：病历碎片化——每次都重来。**  
每次复诊，患者需要从头描述自己的病史——症状、上次的诊断、吃过的药。因为上次的处方是潦草手写在纸上的——可能在裤子口袋里洗烂了，可能在抽屉里找不到。

**痛苦二：看不清也看不懂。**  
手写处方上的拉丁文和缩写——患者只能靠医生口头说"吃这个，一天两次"。从诊所出来 10 分钟后就忘了具体剂量。药品名看不懂，副作用不知道。

**痛苦三：花的什么钱？**  
前台说"500 卢比"。但 500 是什么——诊费？药费？检查费？没有收据，没有记录。下次来的时候，不记得上次花了多少。

**痛苦四：全靠自己记。**  
什么时候该复诊——自己记。药吃了没——自己记。检查报告在哪儿——自己找。这个系统假设每个患者都有完美的记忆和组织能力。

**痛苦五（照护者）：远程管理是个黑洞。**  
"我爸说上周去看了医生。医生说了什么？不知道。开了什么药？不知道。下次什么时候复诊？不知道。我只能靠我爸的记忆——而他已经不记得了。"

### 为什么现有消费者健康平台没解决这个问题？

| 平台 | 他们的东西 | 为什么不是 WeCare Pocket 的替代品 |
|------|-----------|--------------------------------|
| Practo | 在线预约医生 + 视频问诊 | 交易层——不碰病历连续性 |
| Apollo 24\|7 | 在线买药 + 化验 + 问诊 | 消费市场——不碰独立诊所的就诊记录 |
| 1mg / PharmEasy | 在线药房 + 化验 | 供应链——不碰病历 |
| eSanjeevani | 免费政府远程医疗 | 公共渠道——不碰私人诊所的连续性 |
| **WhatsApp** | 消息 + 转账 | **"真正的竞争对手"**——99% 的患者已经在用，但无法结构化记录健康信息 |

**空白：** 没有任何消费者产品连接了独立诊所的就诊记录——医生写的东西，患者能用手机看到。

```

Week 3 — 复诊
  ├─ 到了诊所 → 前台："上次什么时候来的？" → 不记得
  ├─ 见医生 → "吃了什么药？" → 重新描述
  └─ 从零开始——跟上次一模一样

Phase 0 — 照护者
  └─ 女儿："爸，医生说了什么？" → "说了好多——我不记得了"
```

## 5. 产品如何解决这些痛苦？

### WeCare Pocket 是什么

WeCare Pocket 是患者的健康护照——一个手机 App，自动接收来自 Doctor OS Lite 诊所的就诊记录。

它不是：
- 在线问诊 App（不是 Practo 的替代品）
- 在线药房（不是 1mg 的替代品）
- 诊断追踪工具（但可以包含化验结果）

**它就是患者的病历——从诊所直接到患者的手机。医生写了什么，患者就能看到什么。**

### 核心设计决策

**决策一：医生驱动的内容生成。** WeCare Pocket 不要求患者自己输入任何病历信息。所有内容都来自由医生批准的真实 SOAP 笔记。没有医生批准 → 没有内容进 Pocket。这保证了准确性——患者看到的不是 AI 幻想或自己填错的。

**决策二：WhatsApp 是桥，不是替代品。** Phase 1（0–12 个月）患者通过 WhatsApp 收到处方和收据——这是他们已经在用的渠道。Phase 2（12+ 个月）才推出独立 Pocket App。WhatsApp 承担了"行为过渡"的角色——患者不需要同时学习两个新工具。

**决策三：家庭照护者不是事后的附加功能。** 从 Phase 2 的第一天起，Pocket 就应设计为多用户管理——一个照护者可以管理父母的病历，而父母不需要自己操作 App。

## 8. 与提供者端 PRD (PRD-1) 的共享数据契约

WeCare Pocket 和 Doctor OS Lite 共享同一个数据库。消费者端不能有独立的数据库——否则两端的数据就会产生分歧。

### 共享核心表

| 表 | 提供者端使用 | 消费者端使用 | 字段约束 |
|----|------------|------------|---------|
| `patients` | 医生查看 + 前台登记 | 患者在 Pocket 中看自己档案 | `phone_number` 是唯一标识——Phase 2 OTP 登录用同一号码 |
| `emr_records` | 医生创建 SOAP 笔记 | 患者看 `patient_summary` | 每笔记必须含 `patient_summary` 字段——患者友好版 2-3 句总结 |
| `consent_management` | 前台记录同意 + 诊所内授权 | 患者查看和撤回同意 | Phase 1 设计需支持患者直接撤回——不能仅前台操作 |
| `audit_logs` | 诊所内部审计 | 患者看"谁看了我的数据" | Pocket 端展示格式：友好版，非 SQL 日志 |

### 数据流向

```
医生批准笔记 (Doctor OS Lite)
    │
    ├─→ emr_records 保存完整 SOAP 笔记
    │
    ├─→ patient_summary 字段生成（患者友好版）
    │       │
    │       └─→ WeCare Pocket 推送通知 + 在 App 中显示
    │
    ├─→ prescription JSON → Pocket 处方管理
    │       │
    │       └─→ 用药提醒自动设置
    │
    └─→ plan.follow_up date → Pocket 复诊提醒
```

**关键约束:** `patient_summary` 必须在医生批准时同步生成——不能异步延迟。Phase 1 即使不展示，AI 也要生成并存储。否则 Phase 2 启动时历史数据断档。

## 9. 商业模式与定价

### 消费者端收入——Phase 2 启动

| 方案 | 月费 | 包含 |
|------|------|------|
| **Pocket Free** | ₹0 | 就诊摘要、处方查看、WhatsApp 收据（医生端患者的基本价值） |
| **Pocket Plus** | ₹199/月 | + 用药提醒、复诊提醒、就诊历史搜索、化验结果追踪 |
| **Pocket Family** | ₹499/月 | + 家庭管理（最多 5 人）、远程照护通知、照护者仪表板 |

**定价说明:** 方向性——未验证。印度消费者健康 App 付费订阅市场尚未成熟。Free tier 作为 Pocket 的"引入层"——先让患者看到价值，再为额外的提醒和家庭功能付费。

**Phase 2 收入目标:** 50+ 家诊所 × 平均 200 名活跃患者 = 10,000 名潜在 Pocket 用户。按 5% Plus 转化 + 2% Family 转化 → ₹1L-2L/月额外 MRR。

## 10. 合规与数据权利

### 患者的数据权利（DPDP Act 2023 消费者视角）

| 患者权利 | 产品如何满足 | 操作方式 |
|---------|------------|---------|
| **知情权** | 每次就诊有清晰的同意说明——"这些数据将被收集：诊断、处方、化验结果。仅 Dr. Sharma 及其团队可查看。" | 首次就诊 OTP 验证签署 |
| **访问权** | Pocket 内可随时查看自己的全部病历——完整的就诊历史 + 处方 + 化验结果 | Pocket App → "我的记录" |
| **删除权** | 患者可请求删除个人数据。系统在 30 天内完成删除（移除个人标识符，保留匿名聚合数据）。 | Pocket App → "设置" → "删除我的数据" |
| **可携带权** | 患者可导出完整病历为 FHIR/PDF 格式——带到另一家诊所或换到另一个系统。 | Pocket App → "导出病历" |
| **撤回同意** | 患者可随时撤回同意——系统停止收集新数据。已有数据仍保留 7 年（法定要求）或按患者要求删除。 | Pocket App → "同意管理" → "撤回" |
| **审计查询权** | "谁看了我的数据？"——患者可查看最近 30 天内访问其记录的所有人（医生、前台、系统管理员）。 | Pocket App → "隐私" → "访问历史" |

### 患者数据隐私设计

- **数据所有权:** 患者的病历归患者所有。诊所是数据控制者（根据 DPDP），citrus 是数据处理者。
- **加密:** 与提供者端同一套加密架构——AES-256-GCM 静态 + TLS 1.3 传输。
- **授权模型:** 患者可主动授权照护者（家人）或第二意见医生查看自己的记录——"分享链接，3 天有效"。

## 11. Phase 1→Phase 2 消费者转化计划

### 消费者端的 Phase 1 准备（0–12 个月）

Phase 1 不做 Pocket App——但为 Phase 2 做好一切准备：

| 准备项 | 为什么重要 | 谁负责 |
|--------|-----------|--------|
| `patient_summary` 字段从 Day-1 生成 | Phase 2 启动时已有历史数据——不是零起点 | CTO + 工程师 |
| WhatsApp 作为主要患者渠道优化 | 培养患者习惯——"处方和收据会发到我手机上" | 创始人 + 前台培训 |
| Phase 2 消费者调研——5–10 名患者面谈 | 验证 Pocket 定价假设和功能优先级 | Founder |
| ABHA 关联为可选（不强制） | 避免患者恐惧——"政府给我健康 ID？不，谢谢" | 产品设计 |

### Phase 1→Phase 2 过渡 (Month 12–14)

```
Month 12: 50+ 诊所留存确认
    │
Month 13: WeCare Pocket Beta
    ├─ 前 5 家试运行诊所的患者受邀
    └─ WhatsApp 推送: "您的病历现在可以在 WeCare Pocket 中查看"
    │
Month 14: WeCare Pocket v1.0 正式发布
    ├─ 所有 50+ 家诊所的患者自动纳入
    └─ Free tier 默认开通；Plus/Family 在 App 内升级
```

### 激活漏斗

```
100 名患者收到 WhatsApp 处方
    ↓ 60% 点击"查看更多"
60 名患者打开 Pocket 预览页
    ↓ 40% 下载 App
24 名患者安装 WeCare Pocket
    ↓ 50% 在 30 天内活跃
12 名患者成为月活用户
    ↓ 20% 升级
2-3 名患者付费 (Plus/Family)
```

**关键洞察:** Phase 2 的前 12 名月活用户不是来自 App Store 搜索——是来自诊所医生的推荐。"Dr. Patil: 下一个 App，你的病历都在里面。"——医生是消费者端的最高效推广渠道。

## 12. 竞品分析——消费者视角

### 为什么消费者健康 App 没有我们的位置？

| 竞品 | 消费者功能 | 为什么不冲突 |
|------|-----------|------------|
| **Practo** | 在线预约、视频问诊、药品订购 | 交易入口——不保存独立诊所的就诊记录 |
| **Apollo 24\|7** | 在线问诊 + 药房 + 化验 + 保险 | 消费市场——不连接独立诊所 |
| **1mg / PharmEasy** | 在线药房 + 化验 | 供应链——不碰病历连续性 |
| **HealthPlix 患者端** | 患者可查看 EMR | 仅限已注册 HealthPlix 的医生——不连接非 HealthPlix 诊所 |
| **Eka PHR** | 患者健康记录 | 面向已注册 Eka EMR 的诊所——半城市独立诊所不在其当前市场 |
| **政府 ABHA App** | 政府健康 ID | 空壳——几乎没有诊所填充数据 |
| **WhatsApp** | 消息 + 转账 | "真正的竞争对手"——但没有结构化病历 |

### 消费者端差异化

| WeCare Pocket 的独特之处 | 为什么消费者会选它 |
|-------------------------|-------------------|
| 病历来自医生批准的真实记录——不靠患者自己填 | 准确性：AI 没有编造我的病历 |
| 自动——不需要手动输入 | 便利性：我不需要学新技能 |
| 连接我看的诊所——不是另一个独立 App | 相关性：我的诊所已经在用 |
| 照护者模式——远程管理家人 | 实用性：女儿在 Mumbai 可以看我爸的病历 |
| 可选 ABHA——不强制 | 信任：我不需要政府 ID 才能用 |

## 13. 不做什么

Phase 2 WeCare Pocket 明确不做：

- ❌ 在线问诊（不是 Practo 替代品——Pocket 不包含视频问诊功能）
- ❌ 在线药房（不是 1mg 替代品——Pocket 不配送药品）
- ❌ 诊断预约（Phase 3——不是 Phase 2 范围）
- ❌ AI 健康建议 / 诊断（Pocket 不提供任何医疗建议——只展示医生已批准的内容）
- ❌ 社区 / 论坛（不做患者社区——保持医疗严谨性）
- ❌ 强制 ABHA 关联（可选——不强制——这是信任设计决策）

## 14. 关键风险与缓解

| 风险 | 概率 | 如果发生了 | 怎么防止 |
|------|------|-----------|---------|
| **患者不下载 App** | 🟡 中 | Phase 2 启动无用户 | WhatsApp 作为桥——先养成"手机上收到我的病历"的习惯；医生推荐（最高效渠道） |
| **患者不信任数字病历** | 🟡 中 | 下载了但不用 | DPDP 同意透明可见——"你的数据，你控制"；WhatsApp 传递（患者熟悉且信任的渠道） |
| **照护者模式复杂度超预期** | 🟡 中 | 家庭管理功能推迟 | Phase 2 初始仅支持"照护者管理最多 2 人"——先证明价值再扩大 |
| **消费者付费意愿低** | 🟡 中 | 升级率 < 5% | Free tier 有足够价值让患者留存；Plus/Family 是增量价值——非必需 |
| **Phase 1 诊所密度不足→Phase 2 延后** | 🔴 高 | Pocket 推迟到 Month 18+ | Phase 1 试运行指标必须达成——50 家诊所留存是硬门槛 |
| **ABHA 关联低→跨诊所价值难体现** | 🟡 中 | Pocket 只是单一诊所的 App | 可选——不强制；先在单诊所证明价值，跨诊所价值随诊所网络密度自然增长 |
